# ADR 0003 — 사람 수정은 원문 재인용으로만, 항상 재검증

- 상태: 채택
- 날짜: 2026-11-26
- 결정자: 사용자 + 전문가 A·B·C 교차 검증 (Gate A)

## 배경

`MISSING_REQUIRED`·`INVALID_DATE`·`INVALID_MONEY`·`UNKNOWN_VENDOR`로 `HOLD`된 문서를
사람이 안전하게 해소할 경로가 없었다. 원문을 고쳐 새로 업로드하는 방법만 있었고,
이 과정에서 기존 문서와의 연결(감사·중복)이 끊겼다.

동시에 이 프로젝트의 핵심 계약은 "근거 없는 값은 승인 불가"다. 사람이 자유롭게 값을
입력할 수 있게 하면 이 계약이 무너진다.

## 결정

1. **근거는 원문 재인용만 허용한다.**
   - 수정 요청은 `excerpt`(원문 부분 문자열) 또는 `char_start`/`char_end`를 가져야 한다.
   - `excerpt`는 원문에 정확히 1회 나타나야 한다. 여러 번이면 span을 명시한다.
   - 재인용 문구를 필드 규칙으로 정규화한 값이 수정값과 같아야 한다.
   - 따라서 **원문에 없는 값을 새로 만들 수 없다.** `MISSING_REQUIRED`는 원문에 값이
     존재하는 경우에만 해소되고, 아니면 재업로드가 유일한 경로다.
2. **수정 후 항상 재검증한다.** 자동 승인은 없다. 상태는 `HOLD → PENDING_REVIEW`까지만
   자동 전이되고, `APPROVED`는 별도 판정 요청으로만 도달한다.
3. **감사는 영구 보존한다.** 수정 전/후 값, 근거 span, 검토자 별칭, 사유를
   `field_corrections`에 append-only로 남기고, `CORRECTION_RECORDED`·`REVALIDATED`
   감사 이벤트를 기록한다. `field_corrections`도 UPDATE/DELETE 트리거로 막는다.
4. **권한은 `reviewer_alias`를 유지한다.** 인증(P-006)은 이번 범위가 아니다. 별칭은
   인증 수단이 아니며, 공개 배포 전 인증이 필요하다는 기존 경고를 유지한다.

## 데이터 모델

- `extracted_fields`: 추출기 원본. **수정으로 덮어쓰지 않는다.**
- `field_corrections`: 사람 수정 이력(append-only).
- API의 `fields`는 추출 원본, `effective_fields`는 수정이 반영된 유효 값이다.
- 화면·검증·상태는 `effective_fields`를 따른다.

## 결과

- 장점: HOLD 해소 경로가 생기면서도 "근거 없는 승인" 계약이 유지된다.
  수정 이력이 별도 테이블에 남아 추출기 품질과 사람 개입을 분리해 분석할 수 있다.
- 단점: 원문에 없는 누락 값은 해결하지 못한다. 이는 의도된 제약이며, 재업로드가 정답이다.
- 범위 제한: 스칼라 필드 6개만 지원한다. 품목 수정은 별도 Gate/후속 페이즈다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 사람 입력값을 자유롭게 허용 | "근거 없는 값은 승인 불가" 계약과 충돌. 감사는 남아도 검증 의미가 사라짐 |
| `human_asserted` 근거 상태를 승인 가능하게 함 | 근거 상태를 하나 더 만들면 규칙·평가·UI가 모두 복잡해지고, 사실상 예외 승인 |
| 수정 후 자동 승인 | 자동 승인 금지 계약 위반 |
| 추출 필드를 직접 덮어쓰기 | 원본·수정 이력 분리가 불가능해져 감사·평가가 훼손됨 |
