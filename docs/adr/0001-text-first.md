# ADR 0001 — 텍스트 우선, OCR은 나중

- 상태: 채택
- 날짜: 2026-11-26
- 결정자: 프로젝트 오너 + 전문가 A·B·C 교차 검증

## 배경

업무 문서 자동화 포트폴리오에서 OCR과 LLM을 처음부터 함께 넣으면, 실제로 검증하려는
**업무 규칙·근거·승인 흐름**의 품질과 **문자인식 품질**이 뒤섞인다. 그러면 지표가 나빠졌을 때
원인이 파서인지, OCR인지, 규칙인지 구분할 수 없고, 면접에서 "왜 이 숫자인가"를 설명할 수 없다.

## 결정

1. MVP 입력은 UTF-8 텍스트 문서(`.txt`)만 받는다.
2. 추출은 외부 API가 필요 없는 결정론적 파서가 기본이다.
3. OCR은 Phase 5 이후 별도 `source_kind=scan` 경로와 별도 평가표로만 추가한다.
4. LLM 추출기는 같은 `ExtractionProvider` 인터페이스 뒤에 두되, 기본 경로가 아니며
   키가 없어도 모든 테스트·평가가 동작해야 한다.

## 결과

- 장점: 실패 원인이 하나로 좁혀지고, CI가 네트워크 없이 재현되며, 근거 span 검증이 정확해진다.
- 단점: "이미지 문서 처리"라는 데모 임팩트가 줄어든다. 대신 **보류·승인·감사**라는
  차별점에 집중한다.
- 재검토 조건: 텍스트 경로의 규칙·근거 테스트가 안정화되고, OCR 평가셋을 별도로 만들 수 있을 때.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| OCR + LLM을 첫 버전에 포함 | 지표 분리 불가, 외부 바이너리 의존으로 CI 재현성 저하 |
| LLM 단독 추출 | 숫자를 생성할 수 있음. 근거 span을 보장하지 못함 |
| PDF 직접 파싱 | 레이아웃 라이브러리 의존성 대비 얻는 것이 MVP에서 작음 |
