# 보류한 결정 (결정 요청)

새 의존성·외부 API·범위 확장이 필요하면 구현하지 않고 여기에 남긴다.
각 항목은 "왜 지금 하지 않는가"와 "무엇이 결정되면 하는가"를 가진다.

## P-001 — 스캔 이미지 OCR

- 상태: 보류 (Phase 5 확장 후보)
- 이유: OCR 품질과 업무 규칙 품질을 같은 지표로 섞으면 실패 원인을 설명할 수 없다.
  Tesseract 등 외부 바이너리 의존성은 CI 재현성을 떨어뜨린다.
- 결정 조건: 텍스트 경로 규칙·근거 테스트가 안정화되고, `source_kind=scan` 전용 평가셋
  (별도 36건)과 별도 지표표를 만들 수 있을 때.
- 구현 시 지켜야 할 것: OCR 신뢰도 임계값 미달 또는 근거 span 미확보 시 자동 `HOLD`.

## P-002 — LLM 추출기 어댑터

- 상태: 보류 (인터페이스만 준비)
- 이유: 숫자 필드를 생성형 모델에 맡기면 근거 span 보장이 어려워진다. 키 없이도 전체
  테스트가 돌아가야 한다는 계약과 충돌한다.
- 결정 조건: 오프라인 스텁 모델로 계약 테스트를 만들고, LLM 결과도 `ExtractionProvider`
  인터페이스와 근거 검증을 통과할 때. CI 기본 경로에는 넣지 않는다.

## P-003 — 필드 단위 사람 수정(보류 해소)

- 상태: 보류 (MVP 제외)
- 이유: "근거 없는 값은 승인 불가" 원칙과 충돌한다. 사람이 고친 값에 어떤 근거를 붙일지
  (원문 재인용? 수정 사유만?) 계약을 먼저 정해야 한다.
- 현재 우회: 원문을 고쳐 **새 문서로 재업로드**하거나, 해소 가능한 규칙은 재검증한다.
- 결정 조건: `human_correction` 필드 모델, 근거 표시 방식, 감사 이벤트 형식에 합의할 때.

## P-004 — Postgres 전환

- 상태: 보류
- 이유: 데모·포트폴리오에는 SQLite로 충분하다. 동시성·다중 인스턴스 요구가 없다.
- 결정 조건: 동시 검토자 2명 이상, 다중 인스턴스 배포, 또는 감사 로그 외부화 요구가 생길 때.

## P-005 — 부가세율 가변화

- 상태: 보류
- 이유: 합성 데이터셋이 10% 단일 세율이다. 세율표·면세·영세율을 넣으면 규칙과 데이터가
  함께 커져 MVP 검증 범위를 넘는다.
- 결정 조건: 실제 세율 규칙이 필요한 데모 시나리오가 정해질 때.

## P-006 — 인증·권한

- 상태: 보류 (명시적 비목표)
- 이유: `reviewer_alias`는 감사 추적용 별칭이며 인증이 아니다. 로그인을 넣으면 데모
  진입 장벽만 높아진다.
- 결정 조건: 실제 사용자별 권한·승인 위임이 요구될 때.
