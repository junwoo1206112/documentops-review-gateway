# 보류한 결정 (결정 요청)

새 의존성·외부 API·범위 확장이 필요하면 구현하지 않고 여기에 남긴다.
각 항목은 "왜 지금 하지 않는가"와 "무엇이 결정되면 하는가"를 가진다.

## P-001 — 스캔 이미지 OCR

- 상태: 보류 (Phase 5 확장 후보)
- 이유: OCR 품질과 업무 규칙 품질을 같은 지표로 섞으면 실패 원인을 설명할 수 없다.
  Tesseract 등 외부 바이너리 의존성은 CI 재현성을 떨어뜨린다.
- 결정 조건: 텍스트 경로 규칙·근거 테스트가 안정화되고, `source_kind=scan` 전용 평가셋
  (별도 36건)과 별도 지표표를 만들 수 있을 때.
- 구현 시 지켜야 할 것: OCR 신뢰도 임계값 미달 또는 근거 span 미확보 시 자동 `HOLD`.
- 시작 전 작성할 입력: [P-001 OCR Gate 결정 패킷](p001-ocr-gate.md). 모든 `미결정` 항목이
  선택값으로 바뀌기 전에는 Phase 16 코드·스키마·의존성을 추가하지 않는다.

## P-002 — LLM 추출기 어댑터

- 상태: **계약 하네스 완료 (2026-11-26), 실제 모델 연결 보류**
- 이유: 숫자 필드를 생성형 모델에 맡기면 근거 span 보장이 어려워진다. 키 없이도 전체
  테스트가 돌아가야 한다는 계약과 충돌한다.
- 완료한 범위: `EXTRACTION_PROVIDER=llm-contract-stub`은 외부 API 없이
  `ExtractionProvider` 결과 계약·근거 검증·provider 실패의 명시적 422를 검증한다.
  기본 경로는 그대로 `deterministic`이며 CI에 키·네트워크·새 의존성이 없다.
- 실제 모델 결정 조건: 허용 모델/데이터 전송·보존/키 관리 책임, 실패 fallback, 독립 평가셋과
  운영 환경이 정해질 때. 상세는 [Phase 17 리뷰](../reviews/phase-17.md).

## P-003 — 필드 단위 사람 수정(보류 해소)

- 상태: **결정 완료 (2026-11-26, Phase 14)**
- 결정(Gate A):
  1. 근거: **원문 재인용만** 허용. 원문에 없는 값은 만들 수 없다.
  2. 수정 후 상태: **항상 재검증**. 자동 승인 없음, `HOLD → APPROVED` 직접 전이 금지 유지.
  3. 감사: 수정 전/후 값·근거 span·검토자·사유를 **영구 보존**(append-only).
  4. 권한: `reviewer_alias` 유지. 인증(P-006)은 도입하지 않는다.
- 결과: 스칼라 필드 6개 수정 API/UI, `field_corrections` 테이블, 감사 2건
  (`CORRECTION_RECORDED`, `REVALIDATED`). 상세는 [ADR 0003](../adr/0003-human-correction.md).
- 남은 범위: 품목(`items[]`) 수정, 수정값 이력의 화면 필터링은 후속 후보.

## P-004 — Postgres 전환

- 상태: 보류
- 이유: 데모·포트폴리오에는 SQLite로 충분하다. 동시성·다중 인스턴스 요구가 없다.
- 결정 조건: 동시 검토자 2명 이상, 다중 인스턴스 배포, 또는 감사 로그 외부화 요구가 생길 때.

## P-005 — 부가세율 가변화

- 상태: 보류
- 이유: 합성 데이터셋이 10% 단일 세율이다. 세율표·면세·영세율을 넣으면 규칙과 데이터가
  함께 커져 MVP 검증 범위를 넘는다.
- 결정 조건: 실제 세율 규칙이 필요한 데모 시나리오가 정해질 때.

## P-006 — 인증·권한

- 상태: 보류 (명시적 비목표)
- 이유: `reviewer_alias`는 감사 추적용 별칭이며 인증이 아니다. 로그인을 넣으면 데모
  진입 장벽만 높아진다.
- 결정 조건: 실제 사용자별 권한·승인 위임이 요구될 때.
