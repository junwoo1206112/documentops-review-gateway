# 공개 읽기 전용 데모 — A/B/C 교차 검증

- 일자: 2026-11-26
- 범위: Render Blueprint로 외부에 노출하는 합성 데이터 데모

## 검토와 반영

| 관점 | 발견 | 반영 |
|---|---|---|
| A. 제품/UX | 빈 새 DB로 기동하면 읽기 전용 공개 URL에 볼 콘텐츠가 없다. | `PUBLIC_DEMO_READ_ONLY=true`일 때 빈 DB에만 커밋된 합성 fixture 4건을 순서대로 적재한다. |
| B. 보안/운영 | HTTP 쓰기만 403이면 화면의 업로드·판정 폼이 남아 사용자가 실패를 유도한다. | 공개 모드에서 모든 쓰기 HTTP 메서드를 403으로 막고, UI에서는 업로드·수정·재검증·판정 폼을 렌더링하지 않는다. |
| C. QA/평가 | 일반 모드와 공개 모드가 섞이거나 재기동마다 중복 적재되면 기준선이 흐려진다. | 공개 플래그에만 한정하고, 문서가 하나라도 있으면 적재하지 않는다. API 목록 4건, UI 폼 부재, POST 403을 회귀 테스트로 고정한다. |

## 수용 기준과 증거

- 일반 로컬 모드의 수동 업로드 흐름은 변경하지 않는다.
- 공개 모드는 합성 `DEMO-0001`~`0004` 네 건을 표시한다.
- 공개 모드의 `POST /api/documents`는 `E_PUBLIC_DEMO_READ_ONLY` 403이다.
- 공개 상세 화면에는 수정·판정 폼이 렌더링되지 않는다.
- 검증 명령: `python -m pytest -q`, `python tools/generate_dataset.py --check`,
  `python -m app.evaluate --dataset fixtures/evaluation`.

## 남은 배포 확인

- 2026-11-26: 공개 URL에서 `/api/health` 200, 문서 목록 4건, 쓰기 차단 403을 확인했다.
- 2026-11-27: 재확인 시 `/api/health`가 **503**이었다. 무료 인스턴스 중단/슬립인지 서비스 문제인지
  구분되지 않으므로, 재배포 후 아래를 다시 확인하기 전까지 "live"로 주장하지 않는다.
- 재확인 항목: `/api/health` 200, 목록 4건, POST 403, `/evaluation`에 두 레이아웃 리포트.
- 무료 인스턴스 재시작으로 SQLite가 초기화되어도 합성 fixture가 다시 적재되는 것이 의도된 동작이다.
