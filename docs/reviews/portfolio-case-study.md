# 포트폴리오 사례 페이지 — 전문가 A·B·C 교차 검증

대상: `docs/reference/DOCUMENTOPS_PORTFOLIO_CASE_STUDY.md`와 README 링크  
목적: 새로운 기능을 주장하지 않고, 이미 검증된 DocumentOps 증거를 채용·포트폴리오 독자가 빠르게 대조하게 한다.

## 판정

| 관점 | 판단 | 반영 |
|---|---|---|
| A. 포트폴리오·제품 | README에는 근거가 충분하지만 30초 안에 읽을 문제·차별점·증거 요약이 흩어져 있다. | 카드 문구, 60초 면접 설명, 문제→설계→증거→한계를 한 페이지에 모았다. |
| B. 신뢰성·보안 | 사례 페이지가 OCR·실제 LLM·실제 고객 문서·운영 효과를 암시하면 신뢰를 잃는다. | 합성 데이터, 읽기 전용 공개 데모, 텍스트 전용, 자동 승인 없음, 미도입 범위를 명시했다. |
| C. QA·증거 | 테스트 수와 지표는 문서가 늘면서 다시 드리프트할 수 있다. | Phase 17-J의 수집 수 가드가 사례 페이지도 검사하도록 확대했다. |

## 발견과 개선

| ID | 문제 | 조치 | 회귀 방지 |
|---|---|---|---|
| PCS-1 | 기존 공용 사이트 원고에는 다른 프로젝트 내용이 섞여 DocumentOps 카드로 바로 쓰기 어려웠다. | DocumentOps 전용 사례 페이지를 추가했다. | README에서 직접 링크한다. |
| PCS-2 | README의 실행·평가·데모 증거가 길게 분산돼 첫 인상에서 핵심을 잡기 어렵다. | 문제·설계·증거·한계와 60초 설명을 한 페이지에 정리했다. | 공개 데모·Release·CI·평가 문서의 직접 링크를 둔다. |
| PCS-3 | 정적 테스트 수를 사례 페이지에 적으면 다음 변경에서 오래된 수치가 될 수 있다. | 실제 `pytest --collect-only` 수와 사례 페이지를 비교하도록 기존 가드를 확장했다. | `test_documented_test_counts_match_collected_suite` |

## 수용 기준

- 모든 수치는 현재 기준선과 링크 가능한 근거를 가진다.
- 합성 데이터·텍스트 전용·읽기 전용·자동 승인 없음·미도입 범위를 명시한다.
- OCR·실제 LLM·인증·다중 인스턴스·실제 업무 효과를 구현 또는 검증한 것처럼 말하지 않는다.
- 공개 데모처럼 시간에 따라 바뀔 수 있는 사실은 확인일을 쓴다.
